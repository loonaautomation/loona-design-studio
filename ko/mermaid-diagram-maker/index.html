Mermaid 다이어그램 만들기 — Mermaid 코드를 붙여 넣으면 다이어그램이 나와요

요컨대: 이 Mermaid 다이어그램 메이커는 Mermaid 구문의 순서도 부분집합을 분석해요 — 그래프 방향, [ ], ( ), { }, (( )) 모양의 라벨이 있는 노드, |라벨|이 있는 화살표 — 그리고 PNG로 다운로드할 수 있는 층을 이룬 다이어그램을 렌더링해요. 파서는 브라우저에서 완전히 실행돼요.

개발자와 기술 문서를 쓰는 사람들은 문서와 AI 챗에서 다이어그램을 Mermaid 텍스트로 설명해요. 그림만 필요할 때 — 슬라이드, 문서, 빠른 검토용으로 — 전체 도구 체인을 설정하는 대신 여기에 코드를 붙여 넣으세요.

설계부터 비공개: 이 도구의 모든 것은 JavaScript와 함께 브라우저에서 100% 일어나요. 데이터, 사진, 디자인은 서버에 절대 업로드되지 않고, 저장되지 않고, 우리가 보지 않아요 - 탭을 닫으면 모든 것이 사라져요.

Mermaid 다이어그램 만들기 사용 방법

  1. 상자에 Mermaid 순서도 코드를 붙여 넣거나 쓰세요. graph TD(위에서 아래)나 graph LR(왼쪽에서 오른쪽)로 시작하세요.
  2. 지원되는 모양을 쓰세요: A[Process], B(Rounded), C{Decision}, D((Circle)) — 그리고 연결 A --> B나 A -->|label| B예요.
  3. 다이어그램은 층을 이룬 레이아웃으로 실시간 렌더링돼요. 지원되는 부분집합 밖의 모든 줄은 캔버스 아래에 보고돼요. 절대 조용히 버려지지 않아요.
  4. 다이어그램의 전체 자연 크기로 PNG를 다운로드하세요.

작동 방법

손으로 만든 파서는 노드 토큰과 연결을 줄 단위로 읽은 뒤, 층을 이룬 레이아웃이 루트(들어오는 화살표가 없는 노드)에서 너비 우선 탐색으로 각 노드에 깊이를 할당하고 각 레벨을 순서대로 채워요. 지원: 순서도/그래프 헤더(TD, TB, BT, LR, RL), 이 페이지에 나열된 노드 모양, 단단하고 라벨이 있는 화살표, 일반 링크(---)예요. 지원하지 않음(설계상, 정직하게 명시): 시퀀스, 클래스, 상태, 간트 다이어그램, 서브그래프, 스타일링 지시어 — 그 줄들은 잘못 렌더링되는 대신 상태 줄에 표시돼요.

실제 예

한 개발자가 AI 챗에서 체크아웃 흐름의 Mermaid 코드를 받아요. 여기에 붙여 넣고, 결정 분기가 의도대로 렌더링되는지 확인하고, PNG를 팀 디자인 문서에 넣어요.

자주 묻는 질문

어떤 Mermaid 구문이 지원되나요?

순서도 부분집합: graph/flowchart TD/TB/BT/LR/RL, 노드 A[..], A(..), A{..}, A((..)), A[[..]], 연결 -->, ---, -., ==> 변형, 그리고 |라벨|이에요. 시퀀스/클래스/간트 다이어그램은 이 렌더러의 일부가 아니에요 — 페이지가 줄이 지원되지 않음을 알려 줘요.

전체 Mermaid 라이브러리를 사용하지 않는 이유는 무엇인가요?

이 페이지는 완전히 자체 완결되고 외부 의존성이 없이 빠르게 유지되도록 손으로 만들었어요. 대부분의 사람들이 붙여 넣는 순서도 부분집합을 다뤄요. 전체 Mermaid.js 라이브러리는 더 많은 다이어그램 유형을 다뤄요.

지원되지 않는 줄에는 무슨 일이 일어나나요?

그것들은 캔버스 아래의 상태 줄에 수집되고 보고돼요("줄 N: 지원되는 부분집합에 없음") — 절대 조용히 무시되지 않아요.

내 코드가 업로드되나요?

아니에요 — 분석과 렌더링은 브라우저에서 100% 일어나요.
